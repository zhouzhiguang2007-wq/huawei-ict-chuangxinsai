# 行迹手册生成器

## 何时使用

用户已有行程，希望把结果做成便于手机查看、分享或现场使用的交互旅行手册时使用。主规划与专项 Skill 负责研究和决策；本 Skill 负责把**已确认或明确标为草案**的数据做成页面。单纯问路线、住宿、景点、天气或拍照时，先由对应 Skill 回答。

本模块接在 `travel-plan-review` 后；`travel-replanner` 修改行程并复核后，用新数据重建受影响的手册。它补足我们原有七个 Skill 的可视化交付，不再平行重做一套旅行规划。

## 接收和核对

从现有行程复用城市、日期、逐日顺序、地点稳定编号、用餐、住宿、预算、天气提示、预约状态、来源与照片。只向用户询问影响手册公开范围或关键内容的缺项。输入字段与样例见 [数据与交付规范](references/input-output.md)。

制作前检查：

1. `travel-plan-review` 的结论和未解决问题已传入；未通过复核的版本在页面醒目标“草案”。
2. 地点顺序、日期和时间来自同一版行程。铁路车次、价格与余票仅沿用经 12306 核实的信息；本模块不自行改写交通事实。
3. 坐标有来源且含坐标系与点位性质；缺坐标的地点保留在时间线，不在位置示意中造点。直线只表示地点先后，不能称为道路导航或实际交通耗时。
4. 仅嵌入用户自有或明确允许本次分发的图片；其他照片保留原页链接和文字说明。`x-xiake` 的拍照指导图须带来源、合成标记和现场复核项。
5. 费用、开放、天气、预约及住宿状态沿用上游的“已核实/估算/待核实”口径，不能把静态页面写成实时查询。

## 生成与验收

将行程整理为规范 JSON，再运行 `python scripts/build_handbook.py <行程.json> <输出目录>`。脚本只使用 Python 标准库，生成 `index.html`、`route.html`、`food.html`、`places.html`；页面离线可打开，位置示意不需要地图密钥。已有输出目录需显式加 `--force` 才会更新四个页面。

逐页打开检查：入口链接、日期筛选、每一天的顺序与时间、餐饮和景点卡片、来源链接、手机宽度下的阅读、图片对应关系。抽查至少三处地点与已复核行程一致；无坐标时确认页面仍有完整时间线。若用户要真实道路底图，可在具备合法底图/有效密钥与路线数据时另接地图能力，并保持本手册的事实来源不变。

交付时提供入口文件、复核状态、未核实项及图片分发范围。不要仅因 HTML 文件存在就宣称手册完成；页面打不开或关键地点缺失时修复后再交付。

## 与现有模块的交接

- `multi-platform-travel-planner`：提供逐日行程、来源和预算口径。
- `travel-accommodation-advisor`：提供已选住宿或住区及房晚条件。
- `x-xiake`：提供有来源的拍照指导图；未获分享许可的图只给链接和描述。
- `travel-plan-review`：提供通过/草案状态和待修问题。
- `travel-replanner`：修改后交回同一数据结构，本模块重建页面。
