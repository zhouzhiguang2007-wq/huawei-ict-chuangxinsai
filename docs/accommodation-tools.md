# 住宿平台工具现状与接入边界

## 1. 官方接口现状（2026-11-06 核实）

| 平台 | 官方 MCP | 公开报价 API | 结论 |
|---|---|---|---|
| 携程 | 无 | 无 | 只能网页读取 |
| 去哪儿 | 无 | 无 | 只能网页读取 |
| 飞猪 | 无 | 无 | 只能网页读取 |
| 同程 | 无 | 无 | 只能网页读取 |
| 美团酒店 | 无 | 无 | 只能网页读取 |
| Booking.com | 无公开 MCP | 有合作方 API（需商务接入） | 活动场景按网页 |
| Agoda | 无公开 MCP | 有合作方 API（需商务接入） | 活动场景按网页 |
| Trip.com | 无公开 MCP | 有合作方 API（需商务接入） | 活动场景按网页 |

**结论：住宿没有可直接接入的官方 MCP 或公开报价 API。** 不要虚构“官方住宿接口”。

## 2. 可用替代

| 能力 | 可用工具 | 说明 |
|---|---|---|
| 酒店位置、周边、距离 | 高德 POI（平台提供或社区 MCP，需 key） | 只解决“在哪、离景点/车站多远”，不含房价 |
| 房型与价格 | 平台网页（携程/美团/飞猪等） | 必须读取实际销售页面 |
| 退改与早餐 | 平台网页 | 同一条报价内比较 |

## 3. 输出规范（已写进 `travel-accommodation-advisor` 规程）

- 位置信息可来自高德 POI，但必须标注来源与查询时间。
- 房价必须标“待销售渠道核实”，不伪造总价、不虚构房态。
- 同一酒店/等价房型无法确认时标 `comparability=unknown`。
- 预算表把住宿费用标为“估算/待核实”，与已核实项分开。
- 不自动登录、不代下单、不提交入住人信息。

## 4. 验证步骤（人工）

1. 在高德 MCP/Web API 中查目标酒店名称，确认能返回 POI ID、地址、距离。
2. 在携程/美团打开同一酒店，记录房型、日期、价格、退改条款。
3. 对比 skill 输出：位置是否有来源、价格是否标待核实、是否未编造房态。

## 5. 后续可升级方向

- 若拿到携程/美团商务 API 或企业级 MCP，再替换网页读取，并在 `plugin.json` 增加 `mcp_servers.accommodation`。
- 在此之前，不做“看起来已对接”的声明。
