# 现场演示脚本

按顺序发送即可覆盖 9 个 skill。建议先演示 3 分钟版，再按需展开 8 分钟版。

## 3 分钟版（覆盖核心链路）

| # | 对 Agent 说 | 触发的 skill | 验收点 |
|---|---|---|---|
| 1 | 帮我做一份贵阳三天两晚的自由行攻略，两个人，预算 3000 元 | 编排器 → 需求分析 → 规划 → 住宿 → 拍照 → 复核 → 手册 | 是否逐轮追问；是否依次调用多个 skill |
| 2 | 你还没问我旅行风格和交通偏好 | 需求分析 + 问卷 | 是否补问历史人文/城市现代、高铁/飞机 |
| 3 | 第二天要赶高铁，住哪里合适 | 住宿 | 是否给出住区对比与退改条件 |
| 4 | 在甲秀楼怎么拍出好看的全身照，朋友帮我拍 | 拍照（x-xiake） | 是否给机位、姿势、拍摄口令 |
| 5 | 把行程做成手机能离线打开的页面 | 手册 | 是否生成 HTML 或给出可打开文件 |
| 6 | 高铁晚点两小时，后面怎么调整 | 重排 | 是否保留已发生段，只改后续 |
| 7 | 还有两小时才上车，附近能逛什么 | 空档（time-pocket） | 是否给去回程+游玩+安全缓冲 |

## 8 分钟版（再加上资料核实与复核）

| # | 对 Agent 说 | 触发的 skill | 验收点 |
|---|---|---|---|
| 8 | 查一下 2026-11-10 洛阳到开封的高铁 | 规划（铁路） | 是否调用 12306-mcp 并标来源与查询时间 |
| 9 | 下周贵阳天气怎么样，要带伞吗 | 规划（天气） | 是否给来源与查询时间，是否给雨天备选 |
| 10 | 帮我检查这个行程有没有时间冲突 | 复核 | 是否列出问题并给出修正 |
| 11 | 预算改成 2000 元 | 重排 + 复核 | 是否只改受影响部分并重新复核 |

## 演示时同步展示的证据

- 调用详情：工具名、入参、返回、耗时。
- 会话上下文：同一 `trip_id` 下需求、天气、住宿、拍照、复核的写入与读取。
- 降级：临时关掉 12306-mcp，重发第 8 句，确认标 `unknown` 而不是编造车次。

## 不要做的事

- 不要现场改代码或临时安装依赖。
- 不要声称未实际执行的校验通过。
- 不要把社区 MCP 结果说成官方 API。
